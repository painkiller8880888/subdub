# Remotion 社内マニュアル動画制作システム — カスタム仕様書

## 1. この文書の位置づけ

本書は、Remotion を中核とする動画自動制作システムを、職場の社内マニュアル動画作成用にカスタマイズした仕様書である。

- 対象は、業務手順、社内システムの操作方法、定型作業などを説明する日本語の社内マニュアル動画とする。
- IT 技術系の一般向け解説、ショート動画、多言語展開、外部公開を目的とした機能は対象外とする。
- 本システムは個人利用とし、第三者へ配布可能な製品形態にはしない。
- 動画および制作システムを社外へ公開する運用は想定しない。
- WebUI の仕様は現時点では TBD とする。

## 2. プロジェクト概要

### 2.1 目的

動画編集ソフトを使わず、動画の全要素を JSON で管理し、Remotion と React によって社内マニュアル動画をプログラム生成する。

狙いは次のとおり。

- 字幕配置、話者切り替え、音声同期、スライド切り替えなどの反復的な編集作業を自動化する。
- 実際の業務操作を収録した動画を、説明スライドや図解と組み合わせる。
- 人間が手順の正確性、説明の分かりやすさ、最終的な品質判断に集中できるようにする。
- 本編動画とサムネイルを、同じ構造化データから再生成できるようにする。
- 制作時の修正を記録し、台本生成ルールやレビュー基準を継続的に改善する。

### 2.2 中核方針

- 動画の Single Source of Truth は、動画ごとに管理する 1 つの JSON とする。
- 動画編集ソフトは使用しない。
- 動画生成 AI に完成映像を生成させない。
- 映像はコード、React コンポーネント、既定のレイアウト部品から構築する。
- ビジュアルは通常スライド、図解、実作業動画の 3 種類に限定する。
- AI の自由度を意図的に制限し、整備済みの選択肢から選ばせることで品質を安定させる。
- AI による検証と人間によるレビューを組み合わせる。
- 外部公開、配布、複数ユーザー、権限管理は対象外とする。

## 3. 入出力仕様

### 3.1 主入力

動画ごとに 1 つの JSON を入力する。JSON には少なくとも次の情報を含む。

- 動画メタデータ
- キャラクター設定
- セクション
- セリフ
- 話者
- 発話時の表情・感情
- 画面表示用の字幕テキスト
- セリフに対応するビジュアル
- 実作業動画の参照先と再生範囲
- BGM
- 背景
- オープニング、エンディング、アイキャッチ等の挿入設定
- サムネイルの構成データ

実際のフィールド名とスキーマの推奨案は 17 章に記載する。

### 3.2 補助入力

- キャラクター画像
  - 表情差分
  - 口の開閉差分
- VOICEVOX で生成したセリフ音声
- BGM・効果音ファイル
- オープニング、エンディング、アイキャッチ等の動画素材
- 実際の業務操作を収録した動画
- 通常スライド・図解用のレイアウトテンプレート
- サムネイル用の背景画像、キャラクター画像、共通 UI 部品

### 3.3 出力

- 本編動画（MP4）
- サムネイル画像

ショート動画、多言語版、チャプタータイムスタンプは出力しない。

### 3.4 参照動画のメディア仕様

元プロジェクトの参照動画から確認できた値であり、本システムの推奨出力値とは異なる場合がある。

| 項目 | 値 |
|---|---:|
| 画面サイズ | 1280 × 720 |
| アスペクト比 | 16:9 |
| フレームレート | 30 fps |
| 動画コーデック | H.264 |
| 音声 | Opus、48 kHz、ステレオ |

本システムの推奨出力値は 17.14 に記載する。

## 4. システム構成

### 4.1 論理構成

1. 題材・対象作業の決定
2. 提供資料と手順の整理
3. 台本生成・レビュー
4. 通常スライド、図解、実作業動画の割り当て
5. VOICEVOX による音声生成
6. 音声長に基づくタイムライン計算
7. Remotion による動画描画
8. プレビュー・修正
9. MP4 レンダリング
10. サムネイル生成
11. 修正ログの蓄積と制作ルールの改善

### 4.2 中核技術

- Remotion
- React
- TypeScript
- JSON による動画定義
- Zod によるスキーマ検証
- OpenCode
- OpenRouter
- VOICEVOX ENGINE
- 独自 WebUI（TBD）

OpenCode を AI エージェントの操作・制作支援環境として使用し、OpenRouter をモデル接続先として使用する。[OpenCode の公式プロバイダー設定](https://opencode.ai/docs/providers)に従って OpenRouter を接続し、モデル選択や追加モデルの設定を `opencode.json` で管理する。

モデル名をコードへ直接埋め込まず、台本生成、台本レビュー、ビジュアル割り当てなどの用途別エイリアスとして設定する。モデル選定の推奨方針は 17.7 に記載する。

### 5.2 セリフ

セリフは 1 発話ずつデータ化する。各セリフは少なくとも次を持つ。

- 一意なセリフ ID
- 話者
- VOICEVOX で読み上げる本文
- 字幕として表示するテキスト
- 表情または感情タイプ
- 発話中に表示するビジュアル
- 発話前後に追加する任意の無音時間

読み上げ用テキストと字幕テキストは分離する。VOICEVOX に読み方を合わせるための表記と、画面上で読みやすい表記が異なる場合に対応するためである。

### 5.3 ビジュアル

セリフまたは複数セリフで構成される場面に、次のいずれかを割り当てる。

#### 通常スライド

- 見出し
- 本文
- 箇条書き
- 注意・補足表示
- 任意の画像

#### 図解

- 手順フロー
- 要素間の関係
- 作業前後の比較
- 処理や判断の分岐

#### 実作業動画

- 業務操作を収録した動画ファイル
- 使用する開始位置と終了位置
- 表示領域の切り抜き
- 拡大率と位置
- 再生速度
- ミュート設定
- 画面上へ重ねる注釈、枠、矢印、強調表示

コードブロック、ターミナル、SNS 投稿、GitHub 情報、統計カード等の IT 技術解説向けテンプレートは採用しない。

## 6. 制作フロー

### 6.1 企画

1. マニュアル化する社内業務または操作手順を決める。
2. 対象者、動画視聴後にできるようになるべき作業、前提知識を定義する。
3. 手順書、操作メモ、既存資料、注意事項などを Markdown またはテキストで入力する。
4. AI とともに、動画で扱う範囲とセクション構成を整理する。
5. 人間が、内容が実際の業務手順と一致していることを確認する。

### 6.2 提供資料と構成の整理

情報収集、外部調査、エビデンス調査は行わない。

1. 人間が提供した手順書、操作メモ、既存資料だけを入力情報として扱う。
2. AI は入力資料を、前提、準備、操作手順、確認方法、注意事項などのセクションへ整理する。
3. 入力資料に存在しない手順や事実を AI が補完しないようにする。
4. 不明点や矛盾は推測で埋めず、要確認事項として出力する。
5. 人間が構成案を確認し、実際の業務手順と異なる箇所を修正する。

### 6.3 台本

1. 確定した構成を基に、2 キャラクターの掛け合い形式で台本を作る。
2. 台本を 1 セリフずつ JSON データにする。
3. AI が次の観点でレビューする。
   - 入力資料にない手順を追加していないか
   - 操作手順の順番が維持されているか
   - 必須操作や注意事項が抜けていないか
   - キャラクター設定からの逸脱がないか
   - 口調が不自然でないか
   - 説明が冗長または曖昧でないか
4. 人間が台本を読み、内容、口調、話者、表情を修正する。

キャラクターの性格と口調は、レビュー基準として参照できる形で文書化する。

### 6.4 ビジュアル

1. 各場面に通常スライド、図解、実作業動画のいずれかを割り当てる。
2. AI は、整備済みのレイアウトタイプから適切なものを選ぶ。
3. 通常スライドと図解には、説明に必要な最小限の情報だけを流し込む。
4. 実作業を見せるべき箇所を洗い出し、人間が操作画面を収録する。
5. 実作業動画について、使用区間、切り抜き、拡大、注釈を JSON で指定する。
6. 全ビジュアルのプレビュー画像を一括取得する。
7. AI が、文字や要素のはみ出し、重なり、低い視認性を確認する。
8. 人間が表示内容と実際の操作が一致していることを確認する。

完成スライドを画像生成 AI に自由生成させず、テンプレートへ構造化データを流し込む方式を採用する。

### 6.5 音声

[VOICEVOX ENGINE](https://github.com/VOICEVOX/voicevox_engine) を使用する。公式 API の `audio_query` で読み上げ用クエリを生成し、`synthesis` で WAV 音声を合成する。

1. キャラクターごとに VOICEVOX の speaker ID または style ID を設定する。
2. セリフごとに `audio_query` を生成する。
3. 必要に応じて話速、音高、抑揚、音量、文前後の無音時間を調整する。
4. `synthesis` で全セリフを個別の音声ファイルとして生成する。
5. 生成音声の再生時間を取得し、タイムライン計算へ渡す。
6. BGM と効果音は、ファイルごとに音量を管理する。

#### 推奨音声形式

- 中間・マスター音声: WAV
- 符号化: PCM 16-bit
- サンプリングレート: 24 kHz
- チャンネル: モノラル

VOICEVOX の生成結果を再エンコードせず WAV のまま保持し、最終動画のレンダリング時に動画用音声へ変換する。これにより、タイムライン計算時の音声長とレンダリング時の音声長の差を避ける。

#### 推奨ファイル命名規則

```text
audio/voice/{projectId}/{sectionOrder}-{lineOrder}_{lineId}_spk{speakerId}_{textHash8}.wav
```

例:

```text
audio/voice/expense-manual/02-014_line-0027_spk3_a1b2c3d4.wav
```

- `sectionOrder` と `lineOrder` は、フォルダー内で再生順に並べるためにゼロ埋めする。
- `lineId` は台本修正後も可能な限り維持する。
- `speakerId` で使用音声を識別する。
- `textHash8` は読み上げ本文と音声設定から計算し、内容変更時のキャッシュ誤使用を防ぐ。
- 同一条件の音声が存在する場合は再生成しない。

### 6.6 タイムライン

Remotion では、各要素の開始位置と長さをフレーム単位で決定する。

1. 各音声ファイルの再生時間を取得する。
2. 音声長から各セリフの duration を計算する。
3. セリフの duration を先頭から順に累積する。
4. 各セリフの開始フレームと終了フレームを確定する。
5. 同じタイムラインへ以下を同期する。
   - 音声
   - 字幕
   - ビジュアル切り替え
   - 実作業動画
   - 口の開閉
   - キャラクターの動き
6. 無言区間は JSON の明示的な設定値から追加する。

音声ファイルの長さを、動画編集における duration の基準とする。

### 6.7 Remotion 描画

- 動画の各フレームを React で描画する。
- Remotion から渡される現在フレーム番号を基準に、位置、透明度、表示内容、実作業動画の再生位置などを計算する。
- 時間経過へ依存する通常の CSS アニメーションは基本的に使用しない。
- 背景、字幕、キャラクター、ビジュアルをすべてフレーム番号から決定し、再現可能な描画にする。

### 6.8 キャラクター演出

- 2 人のキャラクターを使用する。
- 各キャラクターは画面下部の左右へ配置する。
- 表情差分と口の開閉画像を切り替える。
- 発話中のキャラクターだけ口を動かす。
- 台本で指定された感情に合わせて表情を切り替える。
- 発話中は小さく上下に動かし、話者を視覚的に明示する。
- 実作業動画を表示する場面ではキャラクターを縮小または非表示にできる。

### 6.9 背景

- 通常スライド・図解用の共通背景を使用する。
- 背景の動きは説明を妨げない控えめなものとする。
- 実作業動画の場面では、背景より操作画面の視認性を優先する。
- 背景状態は現在フレーム番号から計算し、再現可能にする。

### 6.10 動画全体の構成

- タイトル
- この動画の目的
- 前提・準備
- 操作手順
- 確認方法
- 注意事項
- まとめ
- エンディング

必要に応じてセクション間にアイキャッチを挿入する。一般向け動画の視聴維持を目的とした冒頭ダイジェストは必須としない。

### 6.11 レンダリング

1. 完成した JSON をシステムに読み込む。
2. プレビューで内容を確認する。
3. MP4 としてレンダリングする。
4. 修正が必要な場合は JSON を直し、再レンダリングする。

## 8. 自動検証

### 8.1 データ検証

- Zod で JSON のスキーマを検証する。
- 必須設定の欠落や設定ミスを、音声生成・レンダリング前に検出する。
- 参照している音声、画像、実作業動画が存在することを確認する。
- 実作業動画の開始・終了位置がファイルの再生時間内であることを確認する。
- セクション ID、セリフ ID、キャラクター ID の重複や不正参照を検出する。

### 8.2 レイアウト検証

- 字幕が画面外へはみ出していないかを検証する。
- 通常スライドと図解をプレビュー画像として一括出力する。
- AI が、はみ出し、重なり、コントラスト不足をレビューする。
- 実作業動画上の注釈が対象操作を隠していないか確認する。
- 最後に人間が目視で確認する。

### 8.3 内容検証

エビデンス調査と翻訳検討は行わない。

- AI は、入力資料と台本の間で手順の順序、必須項目、注意事項に欠落がないか確認する。
- AI は、入力資料にない内容が追加されていないか確認する。
- AI は、キャラクターの口調、説明の明瞭さ、用語表記の一貫性を確認する。
- 実際の業務手順として正しいかどうかの最終判断は人間が行う。

## 9. サムネイル

### 9.1 制作方針

サムネイルは、社内で動画を識別しやすくするための表紙画像として作成する。

1. 共通テンプレートを使用する。
2. マニュアル名、対象業務、部門名または対象システム名を入力する。
3. 必要に応じてキャラクターまたは操作画面の代表画像を配置する。
4. レイアウト結果をプレビューする。
5. 完成状態を JSON に保存する。
6. PNG または JPEG として出力する。

### 9.2 制約

- 文言はタイトルと短い補足に限定する。
- 小さい一覧表示でも識別できる文字サイズを確保する。
- 動画ごとに自由なデザインを生成せず、共通テンプレートを使用する。
- タイトル、部門・対象システム名、マニュアル版数を表示できるようにする。
- 外部公開向けのクリック率最適化や広告的な表現は考慮しない。

## 12. デザイン方針

元プロジェクトの画面構成を基礎としつつ、社内マニュアルとして操作画面と文字の視認性を優先する。

- 16:9 の横長画面。
- 中央に白い角丸カードを配置し、その中へ通常スライドまたは図解を表示する。
- 2 人のキャラクターを画面下部の左右に表示する。
- 字幕は画面下部中央へ大きく表示する。
- 字幕は話者ごとに強調色を使い分ける。
- スライド上部に、その画面の結論や操作目的を短い見出しとして置く。
- 画面上端にセクション名を表示する。
- スライドは情報量を絞り、余白を広く取る。
- 実作業動画は可能な限り大きく表示し、重要操作へ注釈を重ねる。
- 装飾的な動きより、操作対象と字幕の読みやすさを優先する。

推奨デザイントークンは 17.13 に記載する。

## 14. コスト・運用方針

- 本システムは単一ユーザーがローカル環境で使用する。
- 配布用パッケージ、マルチユーザー対応、認証・権限管理、外部公開機能は作らない。
- 完成映像を動画生成 AI で生成せず、映像生成単位の従量コストを発生させない。
- VOICEVOX ENGINE はローカルで実行する。
- OpenCode と OpenRouter を利用し、AI モデル呼び出し部分だけを外部サービスへ接続する。
- モデルを用途別に使い分け、OpenRouter の利用コストを抑える。
- AI へプロジェクト全体を無条件に渡さず、各処理に必要な入力だけを渡す。
- OpenRouter の API キーはリポジトリや JSON へ保存せず、環境変数または OpenCode の認証設定で管理する。

## 15. 継続改善

### 15.1 記録対象

- 台本の修正
- 手順順序の修正
- 読み方・イントネーションの修正
- 字幕の修正
- スライドと図解の修正
- 実作業動画の使用区間、切り抜き、注釈の修正
- サムネイルの修正
- AI レビューが指摘した内容
- 制作中に発生した失敗

### 15.2 改善ループ

1. 人間と AI の修正内容をログへ残す。
2. ログから繰り返し発生する修正傾向を分析する。
3. 傾向を台本生成プロンプト、テンプレート、VOICEVOX 設定、レビュー観点へ反映する。
4. 発生した失敗を新しい自動検証またはレビュー項目として追加する。
5. 同じ修正や失敗が再発しにくいシステムへ更新する。

## 16. 機能要件

### 16.1 必須

- JSON から Remotion 動画を生成できる。
- 2 キャラクターの掛け合いを表現できる。
- VOICEVOX でセリフ音声を一括生成できる。
- セリフ音声長からタイムラインを自動生成できる。
- 字幕、音声、口パク、表情、スライド、図解、実作業動画を同期できる。
- 実作業動画の使用区間、切り抜き、拡大、再生速度、注釈を指定できる。
- オープニング、エンディング、アイキャッチを挿入できる。
- JSON をスキーマ検証できる。
- 字幕やビジュアルのはみ出しを検証できる。
- MP4 をレンダリングできる。
- サムネイルを構成し、JSON に保存して画像出力できる。
- 人間と AI の修正内容をログ化できる。

WebUI に関する要件は 7 章の確定後に追加する。

### 16.2 品質要件

- 同じ JSON と素材から同じフレームを再現できること。
- 文字量が変わっても、既定範囲内でレイアウトが大きく崩れないこと。
- 字幕、音声、スライド、図解、実作業動画、キャラクター動作がフレーム単位で同期すること。
- 実作業動画内の文字や操作対象を視認できること。
- AI に完成デザインを自由生成させず、テンプレート制約によって品質を安定させること。
- 機械検証、AI レビュー、人間レビューの段階を通せること。
- 入力資料にない手順を AI が事実として追加しないこと。

## 17. 実装に向けた推奨案と未確定事項

### 17.1 JSON Schema

**推奨案**

- TypeScript の型と Zod スキーマを同じソースから管理する。
- ルートに `schemaVersion` を持たせ、将来のデータ移行に備える。
- プロジェクト、セクション、セリフ、キャラクターには、人間が読める安定 ID を付ける。
- 表示順と ID を分離する。並べ替えても音声キャッシュや修正ログとの対応が壊れないようにする。
- パスはプロジェクトルートからの相対パスで保持する。
- 自動計算できる開始フレームや音声長は入力 JSON の正本にせず、生成キャッシュへ保存する。

**未確定**

- JSON を人間が直接編集するか、WebUI だけから編集するか。
- JSON Schema を外部ファイルとして公開する必要があるか。

### 17.5 データ保存

**推奨案**

- データベースは使用しない。
- プロジェクト JSON、素材、生成音声、キャッシュ、出力、ログをプロジェクト単位のフォルダーへ保存する。
- 完成動画とサムネイルは `projects/{projectId}/output/` へ保存する。
- 生成途中の音声・プレビューは `cache/` と `audio/` へ分離する。
- プロジェクト JSON とプロンプトは Git で履歴管理する。
- 大容量の実作業動画、音声、完成 MP4 は原則として Git の対象外にする。

### 17.6 VOICEVOX

**推奨案**

- VOICEVOX ENGINE をローカル HTTP API として起動する。
- API の接続先は環境変数 `VOICEVOX_ENGINE_URL` で設定し、既定値を `http://127.0.0.1:50021` とする。
- `audio_query` の結果を必要に応じてキャッシュし、イントネーションの手修正を保持できるようにする。
- speaker ID、話速、音高、抑揚、音量、前後無音をキャラクター設定として持つ。
- セリフ単位でキャラクター既定値を上書きできるようにする。
- 音声ファイルは 6.5 の WAV 形式と命名規則を採用する。

**未確定**

- 使用するキャラクターと style ID。
- 固有名詞・社内用語の辞書登録方法。
- イントネーション修正を JSON に含めるか、VOICEVOX のクエリキャッシュとして保持するか。

### 17.7 OpenCode と OpenRouter

**推奨案**

- OpenCode を、台本作成、台本レビュー、ビジュアル割り当て、検証スクリプト実行の操作環境として使用する。
- OpenRouter は OpenCode のプロバイダーとして接続する。[OpenRouter の API](https://openrouter.ai/docs/quickstart) はモデル接続を単一の API へ集約できるため、モデル変更を制作ロジックから分離する。
- `opencode.json` に用途別エージェントを定義する。
- モデル ID を台本生成ロジックへ直接書かず、次の役割で分離する。
  - `script-writer`: 台本生成
  - `script-reviewer`: 手順の欠落・順序・表現のレビュー
  - `visual-planner`: 3 種類のビジュアルから選択
  - `layout-reviewer`: レンダリング画像の視認性確認
- 台本生成には指示追従性と長文構成力を優先したモデルを使う。
- 分類、形式検証、短いレビューには低コストモデルを使う。
- モデルの出力は自由文で後処理せず、Zod で検証可能な JSON として受け取る。
- モデルの変更を容易にするため、モデル ID とパラメーターは `opencode.json` または環境別設定へ集約する。
- OpenRouter の 429、502、503 に対して、上限付きリトライとエラー記録を行う。

**未確定**

- 各役割へ割り当てる具体的なモデル ID。
- OpenRouter のフォールバックを許可するか、再現性を優先して単一プロバイダーへ固定するか。

### 17.8 キャラクター素材

**推奨案**

```text
public/shared-assets/characters/{characterId}/{expression}/{mouth}.png
```

- 透過 PNG を使用する。
- 全差分でキャンバスサイズ、キャラクターの位置、基準点を統一する。
- 基準解像度は 1024 × 1024 px とし、Remotion 側で縮小表示する。
- 表情は最初から増やしすぎず、次の 4 種類で開始する。
  - `neutral`
  - `smile`
  - `explain`
  - `caution`
- 口は `closed` と `open` の 2 差分から開始する。

### 17.9 口パク

**推奨案**

- MVP では、発話区間中に 4 フレームごとに口の開閉を交互に切り替える。
- セリフ開始時は閉じた状態から始め、終了時は必ず閉じる。
- 無音区間では口を閉じる。
- 切り替え周期はキャラクター設定で変更可能にする。
- より自然な動きが必要になった段階で、音声の音量解析に基づく開閉へ差し替える。

### 17.10 表情

**推奨案**

- 表情はセリフ単位で明示指定する。
- 指定がない場合は `neutral` とする。
- `caution` は注意事項、禁止事項、失敗時の対応に使用する。
- セリフ途中の表情変更は初期実装の対象外とする。

### 17.11 無言区間

**推奨案**

各セリフに次の値を持たせる。

```json
{
  "pauseBeforeMs": 0,
  "pauseAfterMs": 250
}
```

- 通常のセリフ間には短い `pauseAfterMs` を設定する。
- 操作結果を見せる場面では、実作業動画の場面側に明示的な duration を設定する。
- タイムライン内部ではミリ秒をフレームへ丸め、元の JSON では人間が扱いやすいミリ秒を保持する。

### 17.13 デザイントークン

**推奨案**

- フォント: Noto Sans JP
- 基本背景: 濃紺または低彩度のブルーグレー
- コンテンツカード: 白
- 本文色: 濃いグレー
- 強調色: 話者ごとに 1 色
- 注意色: オレンジ
- 警告色: 赤
- 字幕: 白文字、暗色の半透明背景または太い影
- 画面外周セーフエリア: 60 px
- 角丸: 16〜24 px
- 動き: フェードと小さな移動を中心とし、派手な演出は避ける

色の具体値は、実際のキャラクター素材と職場で使用する資料の色に合わせて確定する。

### 17.14 本編動画とサムネイル

**推奨案**

本編動画:

- 解像度: 1920 × 1080
- アスペクト比: 16:9
- フレームレート: 30 fps
- コンテナ: MP4
- 動画コーデック: H.264
- ピクセルフォーマット: yuv420p
- 音声コーデック: AAC
- 音声サンプリングレート: 48 kHz
- 音声チャンネル: ステレオ

実作業動画内の小さな文字を読みやすくするため、元プロジェクトの 720p より 1080p を優先する。

サムネイル:

- 解像度: 1280 × 720
- 形式: PNG を基本とし、容量を小さくしたい場合は高品質 JPEG
- アスペクト比: 16:9

実作業動画:

- 可能なら 1920 × 1080、30 fps で収録する。
- 収録時の拡大率と OS の表示倍率を統一する。
- 通知、個人情報、不要なウィンドウが映らない状態で収録する。

### 17.15 ログ

**推奨案**

- `projects/{projectId}/logs/revisions.jsonl` へ追記形式で保存する。
- 1 行 1 修正イベントの JSON Lines とする。
- 各イベントに次を含める。
  - timestamp
  - projectId
  - targetType
  - targetId
  - source
  - before
  - after
  - reason
  - modelId
  - promptVersion
- 動画生成 1 回ごとの実行情報は `runs/{runId}.json` へ分離する。
- AI の全プロンプト・全応答を常に保存するのではなく、再現と改善に必要な情報を保存する。

## 18. 再現時の完成条件

本システムの初期版が完成したと判断する最小条件は、次の一連の処理が通ることである。

1. 2 キャラクターの複数セリフと、通常スライド、図解、実作業動画を JSON に記述する。
2. VOICEVOX でセリフごとの WAV 音声を生成する。
3. 音声長と明示的な無音時間から、全タイムラインを自動計算する。
4. Remotion で字幕、口パク、表情、キャラクター動作、背景、スライド、図解、実作業動画を同期描画する。
5. JSON スキーマ、素材参照、字幕、レイアウトの検証を通す。
6. 1920 × 1080、30 fps の MP4 を出力する。
7. 共通テンプレートから 1280 × 720 のサムネイルを出力する。
8. 制作時の修正内容と生成結果をログとして保存する。
