# Remotion 動画自動制作システム — 元プロジェクト仕様書

## 1. この文書の位置づけ

本書は、`script.md` と `summary.md` の内容、および同梱された `movie.mkv` の画面・メディア情報から、紹介されている元プロジェクトの仕様を再構成したものである。

- 原文で明言された内容を中心に記載する。
- 映像から確認した内容は「映像で確認」と明記する。
- 原文に具体値や実装名がないものは推測で補わず、「未確定」とする。
- 独自のカスタマイズ案は本書の対象外とする。

## 2. プロジェクト概要

### 2.1 目的

動画編集ソフトや動画生成 AI を使わず、動画の全要素を JSON で管理し、Remotion と React によって動画をプログラム生成する。

狙いは次のとおり。

- 字幕配置、話者切り替え、音声同期、ビジュアル切り替えなどの反復的な編集作業を自動化する。
- 人間が企画、内容の吟味、最終的な品質判断に集中できるようにする。
- 本編、ショート、サムネイル、多言語版を同じ構造化データから量産する。
- 制作時の修正を記録し、プロンプトやレビュー基準を継続的に改善する。

### 2.2 中核方針

- 動画の Single Source of Truth は 1 本の JSON データとする。
- 動画編集ソフトは使用しない。
- 動画生成 AI に完成映像を生成させない。
- 映像はコード、React コンポーネント、既定のレイアウト部品から構築する。
- AI の自由度を意図的に制限し、整備済みの選択肢から選ばせることで品質を安定させる。
- 各工程で AI による検証と人間によるレビューを行う。
- 日本語版で人間の確認を完了してから、他言語版へ展開する。

- 発話時の表情・感情
- 画面表示用の字幕テキスト

- サムネイルの構成データ

### 3.2 補助入力

### 5.2 セリフ

セリフは 1 発話ずつデータ化する。各セリフは少なくとも次を持つ。

- 話者
- 読み上げる本文
- 字幕として表示するテキスト
- 表情または感情タイプ
- 発話中に表示するビジュアル

原文では、驚き、笑顔などの表情を既定タイプから選択する方式が説明されている。

### 5.3 ビジュアル

セリフごとに、その発話中に表示するビジュアルを割り当てる。

原文で例示されたタイプは次のとおり。

- 通常スライド
- 図解
- 比較用 2 列スライド
- コードブロック
- コードの差分表示
- ターミナル出力
- X の投稿表示
- GitHub リポジトリ情報カード
- スター数等の推移グラフ
- 数値を強調する統計カード
- 画面録画
- スクリーンショット

約 10 分の動画に対して、ビジュアルをおよそ 30〜40 個用意する。

## 6. 制作フロー

### 6.1 企画

1. 投稿者が、仕事で使用した技術、SNS で見つけた技術、週末に試した技術などから題材を決める。
2. 動画のターゲットと伝えたい内容を音声入力する。
3. 音声入力を Markdown に書き起こし、「企画の種」とする。
4. AI とともに、誰へ何を伝える動画なのかを整理する。

### 6.2 調査

1. 情報収集担当の AI エージェントが題材を調査する。
2. 情報源をたどり、エビデンス付きの資料として整理する。
3. 別の確認担当 AI エージェントが内容をレビューする。
4. 調査結果からセクション構成と各セクションの目的を言語化する。
5. 人間が WebUI で構成案を確認し、企画趣旨とずれていれば修正する。

### 6.3 台本

1. 確定した構成を基に、2 キャラクターの掛け合い形式で台本を作る。
2. 台本を 1 セリフずつ JSON データにする。
3. AI が次の観点でレビューする。
   - キャラクター設定からの逸脱がないか
   - 口調が不自然でないか
   - 会話や説明が破綻していないか
4. 人間が WebUI 上で読み、以下を修正する。
   - 内容
   - 口調とニュアンス
   - セリフを担当するキャラクター
   - 表情

キャラクターの性格・口調は、レビュー基準として参照できる形で文書化する。

### 6.4 ビジュアル

1. 各セリフに対し、その時間帯に表示するビジュアルを決める。
2. AI は、整備済みのレイアウトタイプから適切なものを選ぶ。
3. 選んだ型に、セリフに必要な最小限の情報を流し込む。
4. 既定の型では収まらない図解に対しても、専用レイアウトや部品パターンを組み合わせる。
5. 操作動画やスクリーンショットが必要な箇所を洗い出す。
6. 人間または撮影用 AI スキルで素材を収録する。
7. 全ビジュアルのスクリーンショットを一括取得する。
8. 専用 AI エージェントが、文字や要素のはみ出し・重なりを確認する。
9. 人間が見た目を最終確認し、必要に応じて修正する。

完成スライドを画像生成 AI に自由生成させる方式は採用しない。情報過多やデザインの不安定化を避けるため、選択肢を制限したテンプレート方式を採用する。

### 6.5 音声

1. 2 キャラクター専用の TTS モデルを使用する。
2. 全セリフを個別の音声ファイルとして一括生成する。
3. キャラクターごとに話速と音量を設定する。
4. BGM と効果音は、ファイルごとに音量を管理する。
5. 多言語版では言語ごとに音声を再生成する。

使用する TTS 製品、音声形式、ファイル命名規則は原文では未確定である。

### 6.6 タイムライン

Remotion では、各要素の開始位置と長さをフレーム単位で決定する。

1. 各音声ファイルの再生時間を取得する。
2. 音声長から各セリフの duration を計算する。
3. セリフの duration を先頭から順に累積する。
4. 各セリフの開始フレームと終了フレームを確定する。
5. 同じタイムラインへ以下を同期する。
   - 音声
   - 字幕
   - ビジュアル切り替え
   - 口の開閉
   - キャラクターの動き
6. 無言区間を作る場合は、明示的な時間調整を追加する。

音声ファイルの長さが、動画編集における duration の基準となる。

### 6.7 Remotion 描画

- 動画の各フレームを React で描画する。
- Remotion から渡される現在フレーム番号を基準に、位置、透明度、表示内容などを計算する。
- 時間経過へ依存する通常の CSS アニメーションは基本的に使用しない。
- 背景、字幕、キャラクター、ビジュアルをすべてフレーム番号から決定し、再現可能な描画にする。

### 6.8 キャラクター演出

- 2 人のオリジナルキャラクターを使用する。
- 各キャラクターは画面下部の左右へ配置する。
- 表情差分と口の開閉画像を切り替える。
- 発話中のキャラクターだけ口を動かす。
- 台本で指定された感情に合わせて表情を切り替える。
- 発話中はゆっくり上下にバウンスさせ、話者を視覚的に明示する。
- キャラクターを小さくし、ビジュアルを大きく見せるレイアウトにも対応する。
- 瞬きは、参照時点では未実装である。

### 6.9 背景

- 静止画ではなく、常に動きのある背景を使用する。
- 背景アニメーションは約 20 種類用意する。
- すべて現在フレーム番号から状態を計算する。

### 6.10 動画全体の構成

- 冒頭ダイジェスト
  - 本編から重要なセリフを約 4 つ抽出して、本編前に提示する。
- オープニング
- 本編セクション
- アイキャッチ
- エンディング

オープニング、エンディング、アイキャッチ、動画背景は一定のルールに従って挿入する。

### 6.11 レンダリング

1. 完成した JSON をシステムに読み込む。
2. 独自 WebUI に組み込んだプレビューで確認する。
3. MP4 としてレンダリングする。
4. 修正が必要な場合は JSON を直し、再レンダリングする。

Remotion 標準の編集 UI は使用せず、独自 WebUI に Remotion のプレビューを組み込む。

## 8. 自動検証

### 8.1 データ検証

- Zod で JSON のスキーマを検証する。
- 必須設定の欠落や設定ミスを、レンダリング前に検出する。

### 8.2 レイアウト検証

- 字幕が画面外へはみ出していないかをスクリプトで検証する。
- 全ビジュアルを一括で画像化する。
- 専用 AI エージェントが、はみ出しや重なりをレビューする。
- 最後に人間が目視で確認する。

### 8.3 内容検証

- 情報収集担当とは別の AI がエビデンスと内容を確認する。
- 台本はキャラクター、口調、論理破綻の観点で AI がレビューする。
- 翻訳はキャラクターの口調、自然さ、原意への忠実さを専用 AI がレビューする。

## 9. サムネイル

### 9.1 制作方針

Canva、Photoshop 等の画像編集ソフトは使わない。完成サムネイルを画像生成 AI で一発生成する方式も基本的に使わない。

1. AI で背景候補を複数生成する。
2. 人間が最も良い背景を選ぶ。
3. AI がテキスト案を複数提示する。
4. 人間が最終文言を決める。AI 案を使わず、独自文言にする場合もある。
5. 背景、テキスト、キャラクターを独自 WebUI のサムネイルエディターで配置する。
6. 完成状態を JSON に保存する。

### 9.2 制約

- サムネイルの文言は 2 行までを基本とする。
- 3 行以上へ情報を詰め込まない。
- 画像、テキスト、座標、レイアウトを構造化データとして保持する。
- 日本語版のレイアウトを基に、他言語版を機械生成できるようにする。
- 必要であれば言語ごとに人間が編集できる。

## 10. ショート動画

- 本編完成後、本編への入口として縦型ショートを制作する。
- 本編とは別のショート用 JSON を作る。
- 同じレンダリングシステムを使用する。
- 本編から見どころを抽出し、短い構成へ再編集する。
- 縦画面向けにレイアウト、字幕位置、進行速度を調整する。
- ショート専用ビジュアルを定義する。
- ショート用サムネイルも生成する。
- AI レビューと人間の確認を行う。

原文では、ショートの最適なフォーマットは引き続き改善中とされている。

## 11. 多言語化

### 11.1 対応言語

日本語を含む 10 言語へ対応する。

1. 日本語
2. 英語
3. 中国語
4. 韓国語
5. ドイツ語
6. フランス語
7. ロシア語
8. ポルトガル語
9. スペイン語
10. イタリア語

### 11.2 翻訳対象

- セリフ
- 字幕
- ビジュアル内テキスト
- サムネイル文言
- タイトル
- 概要欄
- その他、画面上へ表示するすべての文章

### 11.3 処理方式

- 日本語版を人間が確認し、内容を確定してから翻訳する。
- JSON 全体を AI に渡さず、翻訳が必要なテキストフィールドだけを抽出する。
- プロンプトとデータ構造の共通部分は全言語で共有する。
- 言語ごとの差分だけを挿入する。
- 創造性が必要な工程には高性能モデルを使う。
- 定型的な翻訳には軽量モデルを使い、コストを抑える。
- 言語ごとに音声を生成し、同じ Remotion システムでレンダリングする。
- 完成動画を各言語のチャンネルへ投稿する。

## 12. 参照動画から確認できるデザイン

以下は `movie.mkv` の代表フレームから確認できる内容である。

- 16:9 の横長画面。
- 青〜紫系の淡い宇宙・星空風アニメーション背景。
- 中央に白い角丸カードを配置し、その中へスライドや図解を表示。

- 字幕は画面下部中央へ大きく表示。

- 字幕の背後には暗い半透明帯または影を使用し、背景とのコントラストを確保。
- スライド上部に、その画面の結論や要点を短い見出しとして置く。
- 画面上端に小さなセクション名・トピック名を表示。
- スライドは情報量を絞り、余白を広く取る。
- 図、コード、カード、比較、箇条書きを用途別テンプレートとして表示。

色、フォント、余白、角丸、字幕サイズ等の正確なデザイントークンは原文に示されていない。

## 13. チャプター生成

- 各セクションの開始時刻を自動算出する。
- セリフ音声の長さを累積して開始時刻を求める。
- YouTube 概要欄用のチャプタータイムスタンプを自動生成する。
- 人間が手作業で時刻を入力しない。

## 14. コスト・運用方針

- 完成映像を動画生成 AI で生成しないため、映像生成単位の従量コストを抑える。
- Claude Code、Codex 等のサブスクリプション型 CLI サービスの範囲を中心に制作する。
- 高性能モデルと軽量モデルを工程ごとに使い分ける。
- AI へ JSON 全体を渡さず、必要なフィールドだけを渡してトークン消費を抑える。
- 人間は企画、内容確認、最終的なデザイン判断に集中する。

## 15. 継続改善

### 15.1 記録対象

- 台本の修正
- タイトルの修正
- 概要欄の修正
- ビジュアルへの修正指示
- レイアウト調整
- AI レビューが指摘した内容
- 制作中に発生した失敗

### 15.2 改善ループ

1. 人間と AI の修正内容をすべてログへ残す。
2. ログから繰り返し発生する修正傾向を分析する。
3. 傾向を生成プロンプト、テンプレート、レビュー観点へ反映する。
4. 発生した失敗を新しいレビュー項目として追加する。
5. 同じ修正や失敗が再発しにくいシステムへ更新する。

例として、AI が作る抽象的なタイトルを、人間が具体的なツール名・用語を含むタイトルへ直す傾向を分析し、その傾向を生成ルールへ反映する流れが紹介されている。

## 16. 元プロジェクトの機能要件

### 16.1 必須

- JSON から Remotion 動画を生成できる。
- 2 キャラクターの掛け合いを表現できる。
- セリフ音声長からタイムラインを自動生成できる。
- 字幕、音声、口パク、表情、ビジュアルを同期できる。
- 複数の背景アニメーションを切り替えられる。
- 既定のビジュアルテンプレートをセリフへ割り当てられる。
- オープニング、エンディング、アイキャッチを挿入できる。
- 独自 WebUI で台本と動画をプレビュー・修正できる。
- JSON をスキーマ検証できる。
- 字幕やビジュアルのはみ出しを検証できる。
- MP4 をレンダリングできる。
- サムネイルを WebUI で構成し、JSON に保存できる。
- 縦型ショートを同じシステムで生成できる。
- 10 言語へ翻訳し、言語別音声と動画を生成できる。
- チャプタータイムスタンプを自動生成できる。
- 人間と AI の修正内容をログ化できる。

### 16.2 品質要件

- 同じ JSON から同じフレームを再現できること。
- 文字量が変わっても、既定範囲内でレイアウトが大きく崩れないこと。
- 字幕、音声、ビジュアル、キャラクター動作がフレーム単位で同期すること。
- AI に完成デザインを自由生成させず、テンプレート制約によって品質を安定させること。
- 機械検証、AI レビュー、人間レビューの段階を通せること。
- 日本語版の確定内容を保持したまま、多言語版へ展開できること。

## 18. 再現時の完成条件

元プロジェクトを再現できたと判断する最小条件は、次の一連の処理が通ることである。

1. 2 キャラクターの複数セリフとビジュアルを JSON に記述する。
2. セリフごとの TTS 音声を生成する。
3. 音声長から全タイムラインを自動計算する。
4. Remotion で字幕、口パク、表情、キャラクター動作、背景、ビジュアルを同期描画する。
5. WebUI で内容をプレビューする。
6. スキーマと画面はみ出しの検証を通す。
7. 横型 MP4 を出力する。
8. 同じデータ構造から縦型ショートを出力する。
9. 日本語のテキストフィールドを別言語へ差し替え、別音声で同じ動画を出力する。
10. 修正内容をログとして保存する。
