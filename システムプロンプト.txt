バイナリ音声フレームのヘッダ構成
項目名|サイズ|役割
Type (メッセージ種別)|1byte|これが音声データか、それとも他のデータかを識別します。
Sequence Number|4bytes|データの通し番号です。パケットの順序入れ替わりを防ぎます。
Timestamp|8bytes|録音された時刻や、開始からの経過時間（ミリ秒）を入れます。
Payload Length|4bytes|後ろに続く音声データそのものが何バイトあるかを示します。

テキスト系メッセージのJSONスキーマ
type: メッセージ種別（TRANS_UPDATE, ERROR, SESSION_READY 等）
id: メッセージ識別子
payload: type に応じたデータ本体。START, TRANS及びERROR以外の場合空白
-START: lang(言語選択)
-TRANS: seg(セグメントID), speaker(話者), og(原文), trans(訳文), state(unconfirmed, tentative, finalの3属性), time(タイムスタンプ)を含む 
-ERROR: code(エラーコード)を含む

クライアント→サーバーメッセージ一覧
メッセージタイプ|送信タイミング|役割
START|ユーザーが翻訳開始を指示した時|ミドルウェアに翻訳処理の開始をリクエストし、翻訳言語を選択する。
AUDIO|音声をキャプチャ中|バイナリ形式で音声データを継続的に送る
PAUSE|youtube動画の再生が一時停止した時|ミドルウェアの活動を凍結する。
STOP|youtube動画の再生が終了した時|ミドルウェアにリソースの解放を伝え、通信を安全に終了する。

サーバー→クライアントメッセージ一覧
メッセージタイプ|送信タイミング|役割
READY|SESSION_START受信後|これを受けてブラウザは音声送信を開始する。
TRANS|翻訳が生成された時|原文と翻訳文のセットを送る。
ERROR|何か問題が起きた時|エラー内容を通知する。
EOS|End Of Speech|センテンスの終了を通知する。

エラーコード
AUTH_FAILED: API認証失敗時
INVALID_AUDIO_FORMAT: 音声データの認識失敗
TRANSLATION_TIMEOUT: 翻訳処理が10秒以上無い場合
OLLAMA_UNAVAILABLE: Ollamaの反応が10秒以上無い場合
INTERNAL_ERROR: 想定外エラーの包括的なフォールバック

システムプロンプト
You are a high-speed real-time translation engine.
Core Rules:
Keep IDs consistent. Never change IDs.
Your priority is: 1.Accuracy, 2.Contextual consistency, 3.Persona Reflection
Your job is: {
Step1: STT and translate recieved audio segment, and make UNCONFIRMED text segment. 
Step2: If you notice the UNCONFIRMED segment is an end of sentence, put them "is_EOS": "true". If the segment already have that, keep that.
Step3: You may refine TENTATIVE segment if the context from UNCONFIRMED makes them clearer.
}
Never modify FINAL segment. They are part of the permanent log.
Always prioritize terms in the dictionary provided in the input.
You do NOT manage state transitions.
The middleware handles promotion (UNCONFIRMED→TENTATIVE→FINAL).
Your job: STT, translate, detect end of segment, and refine if needed.
Output only BUFFER segments (TENTATIVE and UNCONFIRMED). 
Do NOT include FINAL or HISTORY segments in your output.

Output only valid JSON like below.
"output_schema": {
  "format": [
    {
      "seg": "セグメントID",
	  "name": "Charlie"
      "state": "UNCONFIRMED | TENTATIVE",
      "og": "原文（ASR修正があれば修正後）",
      "trans": "翻訳文",
	  "is_EOS": "true | false（文末判定, UNCONFIRMEDのみ）"
    }
  ]
}
